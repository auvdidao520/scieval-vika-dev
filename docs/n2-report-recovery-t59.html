报告恢复与 Worker 投递意图

阶段记录 · 2026-11-12 · 基线 5a77cce · 分支 scieval/next-stage-t59

本阶段结果：评测事件漏投时可以查询当前评测恢复报告；报告校验、状态变更和待投递意图一起存入 OV 单个文档，重启后可重新读取。投递后由调用方确认，重复报告不会生成第二条意图。

代码执行流程

Worker 绑定 task → 快照 + 提交意图 → 幂等提交 → evaluating
                                             │
                事件漏投 / 重启 ──→ 按 evaluation_id 主动查询
                                             │
                         pending ──→ 保持状态，稍后再查
                         已完成  ──→ 必须包含稳定 report_id
                                             ↓
                        验证 job / 轮次 / 哈希 / 评测 ID / rubric / 13 项
                                             ↓
                         同次写入：报告 + 状态 + 待投递意图
                                             ↓
                  调用方读取待投递 → 目标系统持久路由 → 显式确认
                         ↑                              │
                         └──── 未确认时重启后重试 ──────┘

边界与后续

尚未接通 Vika task_create / task_route 和 inbox，也未完成真实 Worker 两轮、真实 OV / SciEval 联调。Vika task_route 要求可信 inbox 事件引用；本阶段意图 ID 不能直接充当 trigger_id。目标路由成功后、确认前崩溃会重试，目标侧需要去重或对账，不能声称恰好一次。旧状态已处理报告不会自动补投。业务评分与审批规则尚未确认，不能自动发布。
