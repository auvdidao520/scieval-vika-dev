本次结果

新增改稿上下文校验入口，将 job/task 候选映射、上一轮报告和下一轮方案关联检查。避免仅凭非空报告 ID 就把其他任务或其他轮次的报告当成改稿依据。入口只检查调用方提供的数据，不写入存储，也不派工。

代码流

  1. 调用方从可信存储取得 job ID 和上一轮快照 SHA-256，连同候选映射、报告、方案与下一轮号传入 validate_revision_context。
  2. validate_task_binding 检查映射格式，绑定 job 必须等于可信 job；下一轮至少为 2，摘要为 64 位小写十六进制。
  3. framework.validate_report 检查报告的 job、上一轮号、输入摘要及 13 项评分结构。然后要求非空 evaluation_id，并由 validate_plan 检查方案引用一致、动作覆盖目标。
  4. 不匹配抛出异常，调用方必须拦截并转为可处理的修正流程；本入口的成功不授予执行或发布权限。
