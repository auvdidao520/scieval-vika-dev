任务路由重试与恢复

阶段 t60，基于 t59 的 79bcdee。为 Vika 任务路由加入可重试的持久去重，减少成功写入后确认丢失导致的重复输入。

变化

同一任务、同一已接收输入的数据库序号和同一角色再次路由时，不再重复插入。一次调用内重复的输入也只记录一次。已有输入若改用不同角色，整批事务回滚。已完成任务收到重复路由不会再次启动；若提交已落库但任务仍在队列，重试会再次请求调度。重启时现有任务恢复逻辑继续处理 queued/running 状态。

公开的 task_route 仍通过 ActionService 将 event ID 解析为已接收的 connector_events 记录；未知或有歧义的引用会被拒绝。去重键是这些记录的数据库序号与任务 ID，不是调用者提供的报告 ID。

验证

任务管理器测试覆盖重复路由、同批重复、角色冲突的事务回滚、完成后的重试，以及原有 SIGKILL 恢复场景。Python 原型测试使用模拟服务和本机替身，不代表真实服务联调。

边界和后续

本阶段只完成路由重试基础，不代表 SciEval 报告已经自动绑定到可信 inbox 事件或目标任务。t59 的本地 outbox event_id 不能作为 Vika trigger_id；跨 OV 和 Vika 的提交不是一个事务，不能宣称端到端恰好一次。

后续仍需将可信 connector 事件与 job、evaluation、task 的关联持久化并验证，解决查询恢复但没有可信 inbox 事件时的受控接入和对账，再连接报告投递确认。旧数据可能已有重复 task_inputs，本变更不清理历史记录。去重仅针对同一任务，不阻止显式将同一输入路由到其他任务。

尚未与真实 SciEval、OpenViking 和 Worker 做端到端联调，不应据此启用自动发布。该分支继承 t59 的未合并依赖，合并时需协调并行工作。
