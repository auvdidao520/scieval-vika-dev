可信事件投递对账：阶段记录

阶段 t61，基于 t60 的 89e22ae。本阶段加入报告投递对账原型，尚未接通运行中的 Vika 和 OpenViking。

实现

deliver_pending 从作业状态中读取未确认投递意图，要求可信网关查找已接收的 SciEval 事件。它核对 connector、事件种类和 ID、job、round、evaluation、报告正文摘要以及已绑定的 task；缺少事件时保持待处理，歧义或内容不符时拒绝投递。调用网关路由成功后才确认投递意图；确认丢失时可重试，要求网关使用 Vika 已有的按任务及接收序号去重。

验证

Python 单元测试共 25 项通过，包含无事件等待、正文不匹配、事件歧义、路由异常后保留意图和重试确认。测试网关及 OpenViking 均为替身，没有验证真实服务。

尚未完成

目前没有生产网关实现，也没有将本函数挂入 Vika 调度器。可信网关必须从 Core 持久化的已接受事件读取，验证指定的 connector 实例，并调用 TaskManager 路由实际账本记录；不能接受模型或外部调用者自行构造的事件。还需解决作业和 task 创建绑定后的崩溃对账，以及对查询恢复但缺失可信事件的运维处理。因此这个阶段不能称为端到端接通，也不能启用自动投递。

OV 写入和 Vika 路由不是一个事务，依赖幂等重试，不保证端到端恰好一次。分支继承 t55–t60 的未合并工作，审核和合并时需协调依赖。
